# 지도 경로 생성과 강화학습 동작

이 문서는 서울 쾌적 경로 앱이 사용자 입력을 받아 지도에 일반 경로와 맞춤 경로를
표시하기까지의 과정을 설명합니다. 안심·겨울 경로는 공공 안전을 보장하는 경로가 아니라
제공 데이터에 근거한 참고용 추천입니다.

## 한눈에 보는 경로 생성 과정

```text
출발지·도착지·모드 입력
        ↓
주소를 위도·경도로 변환하고 서울 범위 확인
        ↓
보행 그래프 준비
  실제 모드: 오프라인 OSM → 온라인 OSM → 합성 fallback
  샘플 모드: 작은 합성 그래프
        ↓
각 보행 edge에 모드별 공간 지표 결합
        ↓
거리 기준 일반 최단 경로 계산
        ↓
저장 RL 정책 로드 또는 제한된 부분 그래프에서 Q-learning
        ↓
RL 추론 실패 시 weighted A* fallback
        ↓
25% 우회 제한 검사
        ↓
일반 경로와 맞춤 경로를 지도에 함께 표시
```

## 1. 사용자 입력과 좌표 변환

사용자는 출발지, 도착지와 여름·가을·겨울·안심 중 하나를 선택합니다.

- 샘플 모드는 서울역, 서울시청, 광화문 등 미리 등록된 좌표를 사용합니다.
- 실제 모드는 Nominatim 지오코딩을 사용합니다.
- 주소 검색이 실패해도 입력이 등록된 예제 장소라면 예제 좌표를 사용할 수 있습니다.
- 직접 좌표 입력도 지원합니다.
- 출발지와 도착지는 서울 경계 안에 있어야 하며 서로 달라야 합니다.

주소를 찾지 못하거나 서울 밖 좌표라면 경로 계산을 시작하지 않고 이해할 수 있는 오류를
표시합니다.

## 2. 실제 보행 네트워크 준비

실제 모드에서는 다음 순서로 보행 그래프를 준비합니다.

1. 프로젝트의 `data/processed/seoul_walk.sqlite3.gz`를 `cache/`에 해제합니다.
2. 출발지와 도착지를 포함하는 영역만 RTree 공간 인덱스로 조회합니다.
3. 첫 조회 범위에서 연결 경로가 없으면 범위를 단계적으로 넓힙니다.
4. 오프라인 그래프를 사용할 수 없으면 OSMnx로 온라인 Overpass 조회를 시도합니다.
5. 오프라인과 온라인 OSM이 모두 실패해야만 합성 fallback 그래프를 사용합니다.

오프라인 그래프는 2026-09-07 OpenStreetMap 대한민국 PBF에서 서울 영역의 보행 가능한
도로를 추출한 것입니다. motorway, trunk, 공사·계획 도로와 보행 금지 또는 사유지로
명시된 구간은 제외합니다. 하나의 도로를 실제 geometry의 연속 좌표 사이 선분으로 나누고,
각 선분의 길이를 미터 단위로 계산합니다.

따라서 지도 경로 거리는 출발지와 도착지의 직선거리가 아니라 실제 연결된 도로 선분
길이의 합입니다. 출도착 좌표는 가장 가까운 보행 노드에 연결됩니다.

## 3. 일반 최단 경로

일반 경로는 NetworkX 최단 경로 알고리즘으로 계산합니다.

- edge 비용: 해당 보행 선분의 실제 길이(m)
- 목표: 전체 이동 거리의 합이 가장 작은 연결 경로
- 예상 시간: `거리 ÷ 분당 75m`, 즉 시속 4.5km 가정

이 경로는 쾌적 지표를 고려하지 않은 비교 기준입니다.

## 4. 공간 지표를 보행 edge에 결합하는 방법

실제 모드는 경로 주변의 서울 공공데이터를 보행 edge와 결합합니다. 모든 점수는
0~1 범위로 제한됩니다.

| 모드 | 사용하는 값 | edge 점수 생성 방식 |
|---|---|---|
| 여름 | 가로수, 그늘막 | edge 15m 이내 가로수와 35m 이내 그늘막의 밀도를 `shade_score`로 변환 |
| 가을 | `은행나무 암나무` | edge 18m 이내 암나무 수를 `ginkgo_risk`로 변환 |
| 겨울 | 도로 열선 | OSM 도로명과 열선 설치구간 도로명이 일치하면 `heating_score=1` |
| 안심 | 가로등 | edge 25m 이내 가로등 밀도를 `light_score`, `safety_score`로 변환 |

중요한 데이터 제한은 다음과 같습니다.

- 성별이 명시되지 않은 일반 `은행나무`는 암나무로 추정하지 않습니다.
- 열선 원본에는 좌표와 실시간 가동 상태가 없어 도로명이 확인된 edge에만 반영합니다.
- 실제 결빙 위험 자료가 없어 실제 모드의 `icing_risk`는 0입니다.
- 가로등 위치는 조도, 점등, 고장이나 범죄 위험을 의미하지 않습니다.
- 공간 근접도 점수는 MVP용 proxy이며 실제 그늘 면적이나 안전성을 보장하지 않습니다.

## 5. weighted A* 경로

weighted A*는 거리와 선택 모드 지표를 함께 edge 비용으로 사용합니다.

```text
조정 edge 비용 = edge 길이 × 모드별 비용 계수
```

- 여름: 그늘 점수가 높으면 비용 감소
- 가을: 은행나무 암나무 위험이 높으면 비용 증가
- 겨울: 결빙 위험은 비용 증가, 열선 점수는 비용 감소
- 안심: 가로등·야간 보행 점수가 낮으면 비용 증가

비용 계수의 최솟값은 0.2이므로 음수 edge 비용은 발생하지 않습니다. A* heuristic은
현재 노드와 목적지 사이의 직선거리를 사용하지만, 이는 탐색 순서를 빠르게 정하기 위한
값일 뿐 최종 경로 거리가 아닙니다.

weighted A*는 RL을 사용할 수 없을 때 맞춤 경로를 생성하는 안전한 fallback입니다.

## 6. 강화학습 모델

### 왜 부분 그래프를 사용하는가

서울 전체에는 백만 개 이상의 보행 노드가 있습니다. 전체 그래프를 하나의 tabular
Q-learning 환경으로 사용하는 것은 메모리와 학습 시간 면에서 현실적이지 않습니다.

실제 모드는 먼저 일반 최단 경로를 계산한 뒤 그 경로 주변 200m 안의 노드만 남겨 학습
환경을 만듭니다. 이 제한된 부분 그래프에서도 행동은 실제로 연결된 인접 edge 선택입니다.

### 상태

Q-learning 상태는 다음 세 값으로 구성됩니다.

```text
(현재 노드, 목적지 거리 구간, 현재 위치의 모드 지표 구간)
```

- 현재 노드: 보행 그래프에서 사용자의 현재 위치
- 목적지 거리 구간: 목적지까지 남은 직선거리를 4단계로 구분
- 모드 지표 구간: 현재 노드에서 선택할 수 있는 edge의 쾌적 점수를 3단계로 구분

### 행동

행동은 현재 노드에서 직접 연결된 이웃 노드 하나를 선택하는 것입니다. 존재하지 않는
edge로 이동하거나 지도 밖으로 순간 이동할 수 없습니다.

### 보상

한 edge를 이동할 때 다음 항목을 합산합니다.

| 항목 | 효과 |
|---|---|
| 목적지 도착 | 큰 양의 보상 |
| 이동 거리 | 거리가 길수록 음의 보상 |
| 목적지에 가까워짐 | 가까워진 거리만큼 양의 shaping 보상 |
| 모드 쾌적 점수 | 선택 모드에 유리한 edge에 양의 보상 |
| 재방문 | 반복 루프를 줄이기 위한 음의 보상 |
| 25% 초과 우회 | 학습 episode를 종료하고 큰 음의 보상 |

진행 거리 보상은 학습이 목적지 방향을 발견하도록 돕는 reward shaping입니다. 최종 경로는
여전히 실제 edge 연결과 우회 제한을 통과해야 합니다.

### 학습과 저장

- 알고리즘: tabular Q-learning
- 실제 모드 episode: 모드별 1,500회
- random seed: 42
- 탐험: epsilon을 1.0에서 0.03까지 점진적으로 감소
- learning rate: 0.18
- discount factor: 0.95
- 최대 step: 기준 경로 노드 수에 따라 80~600회
- 평가: 학습 전 무작위 정책과 학습 후 greedy 정책을 별도로 실행

그래프 내용, 출도착 노드와 모드가 같은 정책을 다시 사용할 수 있도록 모델과 metadata를
`models/runtime/`에 저장합니다. 그래프 지문이나 모드가 달라지면 잘못된 Q-table을
재사용하지 않고 새로 학습합니다.

샘플 모드의 고정 예제는 `models/q_policy_summer.joblib`에 미리 학습된 정책을 사용합니다.

### 추론

학습 후에는 현재 상태에서 Q값이 가장 높은 이웃 행동을 선택합니다. 이미 방문한 노드로
즉시 돌아가는 행동은 가능한 경우 제외합니다. 각 이동 후 다음을 검사합니다.

- 목적지 도착 여부
- 같은 노드 반복 여부
- 학습하지 않은 상태인지
- 최대 이동 횟수 초과 여부
- 일반 경로 대비 25% 초과 우회 여부

검사를 모두 통과해 목적지에 도착한 경우에만 지도에 `RL 정책` 경로로 표시합니다.

## 7. AI 모델이 나타낼 수 있는 상황

| 화면의 생성 방식 | 발생 상황 | 앱의 처리 |
|---|---|---|
| `RL 정책` | 정책이 목적지에 도달하고 우회 제한을 만족 | RL 경로를 맞춤 경로로 표시 |
| `weighted A* fallback` | 모델 누락, 그래프 지문·모드·구간 불일치 | 공간 지표 기반 A* 경로 표시 |
| `weighted A* fallback` | 미학습 상태, 반복 루프, 최대 step, 미도달 | 실패 이유를 표시하고 A* 사용 |
| `일반 경로 fallback` | RL 또는 A* 후보가 일반 경로보다 25% 넘게 우회 | 일반 최단 경로를 맞춤 결과로 사용 |
| 합성 보행망 안내 | 오프라인과 온라인 OSM을 모두 사용할 수 없음 | 합성 경로임을 명확히 표시 |
| 실제 지표 fallback | 실제 데이터 파일을 읽거나 처리할 수 없음 | 합성 지표 사용 사실과 원인 표시 |

RL이 항상 일반 경로와 다른 경로를 만드는 것은 아닙니다. 지표 차이가 작거나 우회 제한이
강하면 같은 경로가 선택될 수 있습니다. 또한 학습 reward가 좋아졌다는 사실만으로 실제
쾌적성이나 안전성이 개선됐다고 판단하지 않습니다.

새로운 실제 구간과 모드를 처음 검색하면 부분 그래프 학습에 약 10~15초가 걸릴 수
있습니다. 같은 조건의 다음 검색은 저장된 정책을 불러오므로 더 빠릅니다.

## 8. 지도에 표시되는 내용

- 회색 굵은 선: 일반 최단 경로
- 모드별 색상 선: RL 또는 fallback으로 만든 맞춤 경로
- 초록 marker: 출발지
- 빨강 marker: 도착지
- layer: 가로수, 은행나무 암나무, 그늘막, 가로등, 정적 따릉이 대여소
- 범례와 결과 카드: 거리, 예상 시간, 쾌적 점수, 우회율, 생성 방식, 모델 버전과
  fallback 이유

지도 선은 그래프 노드의 실제 도로 좌표를 순서대로 연결합니다. 실제 지도 모드에서는
OSM PBF의 세분화된 도로 선분을 사용하므로 출발지와 도착지 사이를 단순 직선으로 잇지
않습니다.

## 9. 관련 코드

- `src/services/routing.py`: 전체 경로 생성 흐름과 fallback 조율
- `src/routing/graph.py`: 샘플·온라인·오프라인 OSM 그래프 로딩
- `src/routing/baseline.py`: 일반 최단 경로
- `src/routing/weighted.py`: weighted A*와 우회 제한
- `src/routing/rl_agent.py`: Q-learning 환경, 학습, 저장, 로딩과 추론
- `src/indicators/real.py`: 실제 서울 데이터를 edge 점수로 결합
- `src/map_view.py`: 경로, 지표 layer와 범례 렌더링
- `scripts/prepare_osm_network.py`: PBF에서 오프라인 서울 보행망 생성
