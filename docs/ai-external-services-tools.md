# AI, 외부 서비스 및 구현 도구

이 문서는 현재 저장소의 실제 구현을 기준으로 피해가!(街) 웹사이트에서 AI가
사용되는 지점, 모델, 외부 서비스와 개발 도구를 설명합니다. 설정만 준비된 기능과
현재 사용자 흐름에서 작동하는 기능은 구분해 기록했습니다.

## 한눈에 보는 처리 흐름

1. 주소를 좌표로 바꾸고 OpenStreetMap 보행 그래프에서 일반 최단 경로를 구합니다.
2. 서울 시설 데이터를 보행 구간에 결합하고, 선택한 모드의 쾌적 점수를 계산합니다.
3. 저장된 강화학습 정책으로 맞춤 경로를 시도하고, 사용할 수 없으면 weighted A*로
   맞춤 경로를 계산합니다.
4. 경로 안내 문장은 규칙 기반으로 생성합니다. 사용자가 음성 안내를 요청한 경우에만
   Gemini TTS가 그 문장을 음성으로 변환합니다.
5. 이동 완료 후 거리·탄소·비용을 코드의 공식으로 계산합니다. 월간 챗봇은 계산된
   집계만 받아 질문에 답합니다.

## 1. AI가 사용되는 부분

| 기능 | 사용 기술 | 하는 일 | AI를 사용할 수 없을 때 |
|---|---|---|---|
| 맞춤 경로 선택 | 자체 tabular Q-learning 정책 | 제한된 부분 그래프에서 계절·안심 지표와 이동 비용을 반영해 다음 보행 구간을 선택 | 정책이 없거나 루프·미도달 등이 발생하면 weighted A*가 맞춤 경로를 계산 |
| 월간 이동 챗봇 | LangChain + Google Gemini | 이번 달과 이전 달의 구조화된 이동 집계 및 최근 대화를 바탕으로 비교, 패턴, 다음 행동을 자연어로 설명 | 템플릿 브리핑으로 기본 월간 요약 제공 |
| 보행 안내 음성 | Google Gemini TTS | 앱이 만든 한국어 길 안내 한 문장을 음성으로 변환 | 문자 안내는 계속 제공하고 음성 생성 실패를 안내 |

### 강화학습 기반 맞춤 경로

강화학습은 외부 생성형 AI가 아니라 이 저장소에서 학습하고 저장하는 경로 선택
정책입니다.

- **상태**: 현재 노드, 목적지까지 남은 거리 구간, 선택 모드 지표 구간
- **행동**: 현재 노드에서 이동할 수 있는 인접 edge 선택
- **보상**: 목적지 방향 진행과 도착에는 보상, 이동 비용·반복 방문·과도한 이동에는
  감점, 선택 모드에 유리한 구간에는 상대적으로 높은 보상
- **재현성**: 고정 random seed를 사용해 동일 조건의 학습을 재현할 수 있게 함
- **저장과 로딩**: Q-table과 학습 메타데이터를 `joblib` 파일로 저장하고 경로 검색 때 로딩
- **안전한 전환**: 모델이 현재 그래프에 적용되지 않거나 경로가 루프에 빠지거나 목적지에
  도달하지 못하면 deterministic weighted A*를 사용

여름은 그늘, 가을은 은행나무 암나무 회피, 겨울은 열선 및 결빙 관련 지표, 안심은
CCTV·안심귀갓길·가로등 지표를 반영합니다. AI 경로는 실제 안전이나 쾌적성을 보장하는
결론이 아니라 제공된 지도와 시설 데이터 범위 안의 추천입니다. 상세한 학습·추론 과정은
[`route-generation.md`](route-generation.md)를 참고합니다.

### LangChain 기반 월간 이동 챗봇

`MonthlyReportChatbot`은 LangChain의 Google Gemini 연결 모듈을 사용합니다. 모델에
전달되는 값은 선택 월과 이전 달의 이동 횟수, 도보 거리, 탄소 절감 추정치, 택시비 절감
추정치 및 최근 8개 대화입니다. 정밀 좌표나 전체 이동 경로는 전달하지 않습니다.

챗봇은 통계를 새로 계산하지 않으며, 코드가 미리 계산한 값을 해석합니다. 데이터에 없는
이동 원인, 건강 효과 또는 안전성을 추측하지 않도록 지시되어 있습니다. 따라서 챗봇의
문장은 참고용이며 원본 집계값이 우선합니다.

### Gemini 음성 안내

출발, 회전 접근, 경로 이탈, 도착 등 현재 상황에 맞는 안내 문장은 앱의 규칙과 경로
형상으로 먼저 결정됩니다. Gemini TTS에는 검증된 현재 안내 문장만 전달되며, 이를
24 kHz WAV 음성으로 변환합니다. 즉, Gemini가 경로를 선택하거나 새로운 회전 지시를
만드는 구조는 아닙니다.

### AI가 아닌 기능

다음 기능은 이름이나 결과가 지능형 기능처럼 보일 수 있지만 AI 모델을 사용하지 않습니다.

- 일반 최단 경로: NetworkX의 최단 경로 알고리즘
- RL 실패 시 맞춤 경로: 지표 가중치를 적용한 weighted A*
- 쾌적 점수와 시설 영향도: 코드에 정의된 정규화 및 가중 합산식
- 맛집 추천: 경로 주변 후보의 위치, 평점, 리뷰 수 등을 이용한 규칙 기반 정렬
- 거리·예상 시간·탄소·택시비 절감액: 설정된 공식과 외부 응답을 이용한 일반 계산
- 따릉이 추천과 월간 집계: 임계값, 인근 대여소 검색 및 로컬 데이터 집계

## 2. 사용된 AI 모델

| 모델 또는 정책 | 사용 위치 | 입력 | 출력 및 비고 |
|---|---|---|---|
| 자체 tabular Q-learning Q-table | 맞춤 경로 탐색 | 부분 그래프의 상태와 가능한 인접 edge | 다음 edge 선택값. `models/`와 런타임 캐시에 `joblib` 형식으로 저장 |
| `gemini-3.5-flash` 기본값 | 월간 이동 챗봇 | 계산 완료된 월간 통계, 이전 달 통계, 질문과 최근 대화 | 한국어 대화 응답. `GEMINI_MODEL`로 모델명을 변경 가능 |
| `gemini-3.1-flash-tts-preview` | 보행 안내 TTS | 현재 한국어 안내 문장 | `Kore` 음색의 WAV 음성 |

Gemini 모델명은 설정값이며 Google 측 제공 상태나 계정 권한에 따라 사용할 수 있는 모델이
달라질 수 있습니다. 두 Gemini 기능은 `GEMINI_API_KEY`가 있을 때만 활성화됩니다.

## 3. 사용된 외부 서비스

| 외부 서비스 | 서비스 설명과 사용 위치 | 필요한 설정 | 장애 또는 키 부재 시 동작 |
|---|---|---|---|
| OpenStreetMap | 공개 지도 데이터. Folium 배경 지도, 보행 네트워크와 도로 형상의 원천 | 기본 사용에는 키 없음 | 포함된 오프라인 서울 그래프를 우선 사용하고, 사용할 수 없으면 친절한 오류 표시 |
| Nominatim | OpenStreetMap 기반 주소 지오코딩 서비스. 입력 주소를 위도·경도로 변환 | 키 없음 | 앱의 서울 예제 장소 또는 직접 좌표 입력 사용 가능 |
| Overpass API | OSMnx가 필요한 지역의 온라인 보행 그래프를 받을 때 사용하는 OSM 조회 서비스 | 키 없음 | 오프라인 전처리 그래프 사용 |
| 서울 열린데이터광장 | 서울 공공시설 데이터 제공처. 현재 앱은 전처리된 가로수·그늘막·열선·가로등·따릉이·CCTV 등을 사용 | CCTV 갱신 시 `SEOUL_OPEN_API_KEY` | 저장소의 전처리 파일을 사용하므로 일반 실행은 중단되지 않음 |
| Google Places API (New) | 맞춤 경로 주변 음식점 후보, 평점, 리뷰 수와 지도 링크 검색 | `GOOGLE_MAP_API_KEY` | TMAP 검색을 시도하거나 추천 기능을 사용할 수 없다고 안내 |
| TMAP POI API | 경로 여러 지점 주변의 음식점 후보 검색 | `SK_TMAP_APP_KEY` 또는 `TMAP_APP_KEY` | Google Places 결과 또는 추천 불가 안내 |
| TMAP Routes API | 사용자가 택시 대체 이동이라고 확인한 경우 자동차 경로의 예상 택시요금 조회 | `SK_TMAP_APP_KEY` 또는 `TMAP_APP_KEY` | 앱 설정의 택시요금 공식으로 추정 |
| Google Gemini API | 월간 챗봇과 음성 합성 모델 제공 | `GEMINI_API_KEY` | 템플릿 브리핑과 문자 경로 안내 유지 |
| 브라우저 위치 서비스 | 사용자의 허용을 받은 현재 위치를 경로 안내 화면에 반영 | 브라우저 위치 권한 | 위치 기반 진행 안내만 제한되며 검색 결과는 유지 |

Google 및 TMAP은 현재 **일반 보행 경로 계산 서비스로 사용하지 않습니다**. 보행 경로는
OpenStreetMap 그래프를 기반으로 계산하고, 두 서비스는 음식점 및 택시요금 보조 기능에만
사용합니다.

### 연결 준비만 되어 있거나 현재 사용하지 않는 서비스

설정에는 `KMA_SERVICE_KEY`, `VWORLD_API_KEY`, `KAKAO_REST_API_KEY`, `OPENAI_API_KEY`가
있을 수 있지만 현재 핵심 사용자 흐름에서는 각각 기상청, VWorld, Kakao, OpenAI 모델을
호출하지 않습니다. 키가 없어도 경로 검색은 동작합니다. 서울 따릉이 실시간 API용 adapter
인터페이스도 준비되어 있으나 현재 화면은 전처리된 대여소 데이터를 사용합니다.

## 4. 사용된 구현 도구

| 도구 | 사용 위치 |
|---|---|
| Python | 애플리케이션, 데이터 전처리, 경로 계산, 모델 학습의 주 언어 |
| Streamlit | 한국어 웹 UI, 입력 폼, 결과 카드, 월간 리포트와 상태 관리 |
| Folium / streamlit-folium | 지도, 일반·맞춤 경로 선, 시설 layer, marker와 범례 표시 |
| NetworkX | 보행 그래프 표현, 일반 최단 경로와 weighted A* 계산 |
| OSMnx | Nominatim 지오코딩과 온라인 OSM 보행 그래프 adapter |
| GeoPandas / Shapely / Pyogrio / pyproj | 공공데이터와 SHP 처리, 좌표계 변환, buffer·거리·인접성 등 공간 연산 |
| Pandas | 시설 데이터와 경로 비교 통계의 표 형식 처리 |
| OpenPyXL | 서울시에서 받은 XLSX 원본 데이터 전처리 |
| LangChain Core / langchain-google-genai | 월간 통계, 대화 이력과 Gemini 채팅 모델 연결 |
| Google Gen AI SDK | Gemini TTS 요청과 음성 응답 처리 |
| Requests | 서울 API, Google Places, TMAP 등 HTTP 요청과 timeout 처리 |
| joblib | 강화학습 Q-table 및 메타데이터 저장·로딩 |
| SQLite | 로그인 없는 월간 이동 집계 저장. 정밀 좌표와 전체 경로는 저장하지 않음 |
| python-dotenv | `.env`의 비밀키와 실행 설정 로딩 |
| streamlit-geolocation | 사용자가 허용한 브라우저 현재 위치 수신 |
| pytest | 경로, 지표, 강화학습, 데이터, 리포트 기능 자동 테스트 |
| Ruff | Python 코드의 정적 검사와 형식 품질 점검 |

## 데이터와 개인정보 경계

- API 키는 `.env`에서 읽고 화면이나 저장소 코드에 직접 표시하지 않습니다.
- 월간 기록은 집계값 중심으로 로컬 SQLite에 저장하며 정밀 좌표와 전체 이동 경로를
  저장하지 않습니다.
- Gemini 챗봇에는 구조화된 월간 집계와 사용자가 입력한 채팅 내용이 전송됩니다.
- Gemini TTS에는 현재 안내 문장이 전송됩니다.
- 주소 지오코딩, 음식점 검색과 택시요금 조회를 사용할 때는 해당 공급자에게 요청에 필요한
  위치 또는 검색 정보가 전달될 수 있습니다.
- 강화학습 추론과 weighted A* 계산은 로컬에서 수행됩니다.

외부 AI와 지도·검색 서비스의 결과는 네트워크 상태, 데이터 갱신 시점과 모델 응답에 따라
누락되거나 부정확할 수 있습니다. 경로, 안심 및 결빙 관련 결과는 참고용이며 현장 상황과
공식 안내를 함께 확인해야 합니다.
