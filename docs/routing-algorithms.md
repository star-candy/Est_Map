# 맞춤 경로 알고리즘 이해하기

이 문서는 현재 코드에 구현된 weighted A*와 tabular Q-learning이 어떤 입력을 받고,
어떻게 경로를 만들며, 두 결과 중 무엇을 화면에 표시하는지 설명합니다. 설명 기준 코드는
`src/routing/weighted.py`, `src/routing/rl_agent.py`, `src/services/routing.py`입니다.

## 1. 먼저 알아둘 용어

보행 지도는 그래프로 표현합니다.

- **노드(node)**: 교차점이나 도로 형상이 꺾이는 지점
- **edge**: 두 노드를 연결하는 실제 보행 가능 도로 구간
- **경로(path)**: 출발 노드부터 도착 노드까지 이어지는 노드 목록
- **edge 길이**: 해당 도로 구간의 길이(m)
- **지표 점수**: 그늘, 은행나무 위험, 열선, 결빙 위험, 가로등·안심 지표를 0~1로
  정규화한 값

두 알고리즘은 같은 보행 그래프와 같은 edge 지표를 사용하지만 경로를 찾는 방식이
다릅니다.

| 구분 | weighted A* | Q-learning |
|---|---|---|
| 성격 | 계산 시점에 최저 비용 경로를 직접 탐색 | 여러 episode를 이동하며 행동 가치를 학습 |
| 결과 근거 | edge 비용의 합 | 학습된 상태·행동별 Q값 |
| 재사용 | 검색할 때마다 계산 | 학습 결과를 파일로 저장하고 같은 조건에서 재사용 |
| 실패 가능성 | 연결 경로가 없을 때 | 미학습 상태, 반복, 미도달, 그래프 불일치 등 |

## 2. 두 알고리즘이 공유하는 edge 비용

맞춤 경로의 기본 비용은 다음과 같습니다.

```text
adjusted_cost
  = edge 길이(m)
  × 보행시설 우선 계수
  × 모드별 비용 계수
```

비용이 낮을수록 그 edge를 선택하기 쉽습니다. 모든 비용은 최소 `0.001` 이상이므로
음수 edge 비용은 없습니다.

### 2.1 보행시설 우선 계수

OSM의 보행 그래프에는 전용 보행로뿐 아니라 걸을 수 있는 일반 도로도 포함될 수 있습니다.
따라서 도로 종류별로 다음 계수를 적용합니다.

| 대표 도로 종류 | 계수 | 의미 |
|---|---:|---|
| `footway`, `pedestrian`, `path`, `corridor` | 1.00 | 전용·명시적 보행시설 우선 |
| `steps` | 1.05 | 계단 |
| `living_street` | 1.04 | 보행 친화 생활도로 |
| `residential` | 1.08 | 주거도로 |
| `service` | 1.12 | 진입·서비스 도로 |
| `tertiary` | 1.35 | 일반도로, 보행시설보다 후순위 |
| `secondary` | 1.55 | 큰 도로, 추가 패널티 |
| `primary` | 1.80 | 주요 간선도로, 더 큰 패널티 |
| `primary_link`, `busway` | 2.00 | 가장 보수적으로 취급 |
| 알 수 없는 도로 종류 | 1.75 | 태그 누락을 보수적으로 처리 |

일반 경로도 `길이 × 보행시설 우선 계수`를 사용합니다. 화면에 표시되는 거리는 이 비용이
아니라 선택된 edge들의 실제 길이 합입니다.

### 2.2 모드별 비용 계수

현재 구현식은 다음과 같습니다. 각 지표는 0~1입니다.

```text
여름:  5.0 - 4.8 × shade_score
가을:  1.0 + 8.0 × ginkgo_risk
겨울:  5.0 + 5.0 × icing_risk - 4.8 × heating_score
안심:  0.2 + 4.8 × (1.0 - safety_score)
```

계수의 최솟값은 `0.2`입니다.

예를 들어 길이와 도로 종류가 같은 두 edge가 있을 때:

- 여름 모드에서 그늘 점수 0인 edge의 계수는 5.0입니다.
- 그늘 점수 1인 edge의 계수는 0.2입니다.
- 따라서 그늘 점수가 높은 edge의 탐색 비용이 훨씬 낮습니다.
- 가을 모드는 반대로 은행나무 위험이 높을수록 비용이 증가합니다.

이 값은 실제 온도, 범죄 가능성 또는 안전 확률이 아니라 경로 탐색을 위한 상대 비용입니다.

## 3. weighted A*의 동작

weighted A*는 출발지에서 목적지까지 누적 비용이 낮을 것으로 예상되는 노드를 우선해서
탐색합니다.

```text
우선순위 = 출발지부터 현재 노드까지의 adjusted_cost 합 + 목적지까지의 추정 비용
```

목적지까지의 추정 비용인 heuristic은 다음과 같습니다.

```text
현재 노드와 목적지의 직선거리 × 0.2
```

직선거리는 실제 경로 거리가 아니라 탐색 순서를 정하기 위한 값입니다. 최종 경로는 반드시
그래프에 실제로 연결된 edge들로 구성됩니다.

동작 순서는 다음과 같습니다.

1. 모든 edge에 선택 모드의 `adjusted_cost`를 계산합니다.
2. 입력 좌표와 가장 가까운 출발·도착 노드를 찾습니다.
3. 누적 비용과 heuristic을 이용해 A* 탐색을 수행합니다.
4. 목적지에 도달한 경로의 실제 거리와 모드 점수를 계산합니다.

weighted A*는 학습하지 않습니다. 같은 그래프와 같은 지표라면 항상 같은 비용식을 이용해
경로를 다시 계산합니다.

## 4. Q-learning의 학습 환경

서울 전체 그래프를 tabular Q-learning으로 학습하면 상태 수가 너무 커집니다. 실제 경로
검색에서는 먼저 일반 경로를 만든 뒤 그 경로 주변 450m 안의 노드를 추출해 부분 그래프를
구성합니다. 출발·도착 노드는 항상 포함됩니다.

### 4.1 상태

상태는 다음 세 값의 튜플입니다.

```text
(현재 노드 ID, 목적지 거리 구간, 현재 위치의 지표 구간)
```

목적지 거리 구간은 현재 노드의 목적지 직선거리를 일반 경로 거리로 나눈 값입니다.

| 비율 | 거리 구간 |
|---:|---:|
| 0.25 이하 | 0 |
| 0.60 이하 | 1 |
| 1.00 이하 | 2 |
| 1.00 초과 | 3 |

지표 구간은 현재 노드에서 이동 가능한 edge 중 가장 높은 쾌적 점수를 3단계로 나눈
값입니다. 현재 노드 ID도 상태에 포함되므로 서로 다른 교차점을 같은 상태로 합치지는
않습니다.

### 4.2 행동

행동은 현재 노드와 직접 연결된 다음 노드 하나를 선택하는 것입니다. 즉 RL 정책도 그래프에
없는 길로 순간 이동할 수 없습니다. 두 노드 사이에 여러 edge가 있으면 길이가 가장 짧은
edge를 환경 이동에 사용합니다.

### 4.3 한 번 이동할 때의 보상

현재 구현의 기본 보상은 다음과 같습니다.

```text
reward
  = -(선택 edge의 adjusted_cost / 100)
    + 목적지에 가까워진 거리(m) / 20
```

여기에 다음 사건 보상이 추가됩니다.

| 사건 | 보상 변화 |
|---|---:|
| 목적지 도착 | +100 |
| 이미 방문한 노드 재방문 | -15 |
| 존재하지 않는 행동 | -30 후 episode 종료 |
| 설정된 우회 한도 초과 | -30 후 episode 종료 |
| 최대 step 안에 미도달 | -20 |

현재 실제 구간 런타임 학습은 고정 우회율 한도를 설정하지 않습니다. 대신 edge 거리 비용,
목적지 진행 보상, 재방문 패널티와 최대 step으로 불필요한 이동을 억제합니다.

중요한 점은 RL이 별도의 새로운 지표식을 배우는 것이 아니라 weighted A*와 동일한
`adjusted_cost`를 보상에 사용한다는 것입니다. 차이는 A*가 전체 후보를 탐색하는 반면,
Q-learning은 반복 경험을 통해 각 상태에서 어느 이웃으로 이동할지 학습한다는 점입니다.

## 5. Q값이 학습되는 방식

Q-table은 상태별로 각 행동의 기대 누적 보상을 저장합니다.

```text
Q(상태, 행동)
  ← 기존 Q값
    + 학습률 × [현재 보상 + 할인율 × 다음 상태의 최대 Q값 - 기존 Q값]
```

현재 기본값은 다음과 같습니다.

| 설정 | 기본 학습 | 실제 검색 런타임 학습 |
|---|---:|---:|
| episode | 4,000 | 1,500 |
| 학습률 | 0.18 | 0.18 |
| 할인율 | 0.95 | 0.95 |
| 시작 epsilon | 1.00 | 1.00 |
| 종료 epsilon | 0.03 | 0.03 |
| random seed | 42 | 42 |
| 평가 episode | 200 | 30 |
| 최대 step | 40 | 일반 경로 노드 수에 따라 80~600 |

### epsilon-greedy 탐험

- 학습 초반에는 epsilon이 1에 가까워 임의 행동을 자주 선택합니다.
- episode가 진행될수록 epsilon을 0.03까지 선형으로 낮춥니다.
- 탐험하지 않을 때는 현재 상태에서 Q값이 가장 높은 행동을 선택합니다.
- Q값이 같은 행동이 여러 개면 seed가 고정된 난수로 하나를 선택합니다.

random seed가 같고 입력 그래프와 설정이 같으면 학습 결과를 재현할 수 있습니다.

## 6. 학습 전후 평가와 모델 저장

학습 전에는 무작위 정책, 학습 후에는 epsilon 0의 greedy 정책을 평가합니다. 저장되는
평가값은 다음과 같습니다.

- 평균 episode 보상
- 목적지 도달률
- 성공 경로의 평균 우회율
- 성공 경로의 평균 모드 점수

이 지표는 학습 동작을 점검하기 위한 값입니다. 평균 보상이 증가했다고 해서 실제 안전성이나
쾌적성이 검증됐다는 의미는 아닙니다.

Q-table과 metadata는 joblib 파일로 저장되며, 사람이 확인할 수 있는 metadata JSON도 함께
생성됩니다. metadata에는 모드, 출발·도착 노드, random seed, 학습 설정, 평가 결과와 그래프
지문이 포함됩니다.

그래프 지문은 노드 좌표, edge 길이와 여섯 지표 점수로 계산합니다. 데이터나 점수가 바뀌면
지문도 달라지므로 과거 정책을 잘못 재사용하지 않고 새로 학습합니다.

## 7. RL 정책 추론

저장된 정책을 사용할 때 먼저 다음을 검사합니다.

1. 현재 그래프 지문이 학습 당시와 같은가?
2. 선택 모드가 같은가?
3. 출발·도착 노드가 같은가?

검사를 통과하면 출발 상태부터 Q값이 가장 높은 이웃을 반복 선택합니다. 가능한 경우 이미
방문한 노드는 후보에서 제외합니다. 다음 상황에서는 RL 후보를 실패로 처리합니다.

- 현재 상태에 학습된 행동이 없음
- 유효한 이웃 행동이 없음
- 반복 루프 감지
- 최대 이동 step 안에 목적지에 도달하지 못함

RL이 실패해도 전체 경로 검색이 바로 실패하지는 않습니다. weighted A* 후보를 계속 사용할
수 있습니다. 현재 추론은 과거 모델 metadata의 25% 우회 제한도 비활성화합니다.

## 8. 최종 맞춤 경로 선택

현재 서비스는 RL을 먼저 학습·추론한 뒤 weighted A*도 항상 계산합니다. 두 완성 후보에 대해
경로 전체의 모드 점수를 길이 가중 평균으로 계산합니다.

```text
경로 점수 = 100 × Σ(edge 길이 × edge 쾌적 점수) / Σ(edge 길이)
```

후보 처리 순서는 다음과 같습니다.

1. 일반 경로의 거리와 모드 점수를 계산합니다.
2. RL 후보와 weighted A* 후보를 계산합니다.
3. 일반 경로보다 모드 점수가 높거나, 점수가 같으면서 더 짧은 후보만 남깁니다.
4. 남은 후보 중 모드 점수가 가장 높은 경로를 선택합니다.
5. 점수도 같으면 더 짧은 경로를 선택합니다.
6. 점수와 거리까지 같으면 RL 후보를 우선합니다.
7. 사용할 후보가 없으면 일반 경로를 맞춤 경로로 반환하고 이유를 표시합니다.

따라서 화면의 `RL 정책`은 RL 후보가 실제 최종 선택까지 통과했다는 뜻입니다.
`weighted A* fallback`은 RL이 실패했거나 A* 후보의 전체 경로 점수가 더 높았다는 뜻입니다.

## 9. 간단한 예시

출발지에서 목적지까지 두 경로가 있다고 가정합니다.

```text
경로 A: 800m, 대부분 그늘 없음
경로 B: 1,000m, 대부분 그늘 있음
```

일반 경로는 보행시설 계수를 포함한 거리 비용이 낮은 A를 선택할 가능성이 높습니다.
여름 weighted A*는 B의 `shade_score`가 높아 edge 비용이 크게 할인되면 B를 선택할 수
있습니다. Q-learning도 B를 이동했을 때 `adjusted_cost` 기반 음의 보상이 작아지므로 반복
학습을 통해 B 방향 행동의 Q값을 높일 수 있습니다.

하지만 다음 상황에서는 기대와 다른 결과가 나올 수 있습니다.

- 지표가 실제 보행 edge에 잘못 결합됨
- 지표가 너무 짧은 일부 edge에만 존재함
- 부분 그래프 450m 밖에 더 좋은 경로가 있음
- 1,500 episode 안에 희소한 유리 행동을 충분히 탐험하지 못함
- 전체 경로 평균 점수 차이가 매우 작음

이때는 지표 결합 결과, edge별 비용, RL 평가 metadata와 최종 후보 점수를 함께 확인해야
합니다.

문제가 생기면 다음 순서로 확인하는 것이 가장 빠릅니다.

1. 해당 지표가 기대한 edge에 0~1 값으로 결합됐는지 확인합니다.
2. 같은 edge의 `length`, `highway`, 보행시설 계수와 모드 비용 계수를 확인합니다.
3. 일반·RL·A* 후보의 거리와 전체 경로 점수를 비교합니다.
4. RL metadata의 도달률, 평균 보상, 그래프 지문과 모드를 확인합니다.
5. 화면의 생성 방식과 RL 후보 제외 사유를 확인합니다.

## 11. 해석할 때 주의할 점

- weighted A*가 선택한 경로가 실제로 가장 안전하다는 뜻은 아닙니다.
- Q-learning의 높은 보상은 실제 환경의 안전성 또는 쾌적성 검증 결과가 아닙니다.
- `safety_score`는 공공 시설 위치 기반 proxy이며 범죄 위험 확률이 아닙니다.
- `shade_score`는 실제 시각별 그림자 면적이 아니라 가로수·그늘막 근접도입니다.
- 열선은 도로명 기반이며 실제 설치 범위와 가동 상태가 다를 수 있습니다.
- 두 알고리즘 모두 입력 그래프와 지표 데이터의 정확도 이상으로 정확해질 수 없습니다.
